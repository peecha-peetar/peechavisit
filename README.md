# پیچا ویزیت | PeechaVisit

سامانهٔ ردیابی و مدیریت ویزیتورهای فروش میدانی — نسخهٔ **۲.۲**
وب‌سایت: [peecha.ir](https://peecha.ir)

ویزیتور با **اپ اندروید** (یا وب‌اپ موبایل) ویزیت مشتری، ثبت سفارش و دریافت‌های مالی
(نقدی / چک / حواله) را به همراه موقعیت GPS و عکس ثبت می‌کند؛ مدیر از طریق داشبورد و
پنل مدیریت، همه‌چیز را روی نقشه و در جدول‌ها می‌بیند و کاربران و تنظیمات را مدیریت می‌کند.

---

## 🔑 اطلاعات ورود پیش‌فرض

> این‌ها کاربران پیش‌فرضی هستند که اسکریپت `create_tables.py` می‌سازد و در دیتابیس فعلی
> شما هم (`tracking.mdf` داخل `DATA.rar`) با همین رمز ذخیره شده‌اند:

| نام کاربری | رمز عبور   | نقش      | کجا وارد می‌شود |
|------------|------------|----------|------------------|
| `admin`    | `admin123` | مدیر     | داشبورد، پنل مدیریت، اپ موبایل |
| `visitor1` | `admin123` | ویزیتور  | فقط اپ موبایل |

رمز به‌صورت `SHA256` ذخیره می‌شود. بعد از اولین ورود، حتماً از پنل مدیریت رمزها را عوض کنید.

## 🧩 اجزای پروژه

| فایل / پوشه | پورت | توضیح |
|------|------|-------|
| `app.py` | `5000` | Flask API — بک‌اند اپ موبایل (توکن HMAC) |
| `run_client.py` | `8000` | سرو کردن وب‌اپ موبایل (`pwa_client/`) |
| `dashboard.py` | `8501` | داشبورد مدیر — ویزیت‌ها، سفارش‌ها، دریافت‌ها روی نقشه (نیاز به ورود مدیر) |
| `admin.py` | `8502` | پنل مدیریت — کاربران، تنظیمات، وضعیت سیستم |
| `android/` | — | پروژهٔ اپ اندروید (APK) |
| `pwa_client/` | — | صفحات اپ موبایل؛ هم وب‌اپ و هم داخل APK از همین‌ها استفاده می‌کنند |
| `config.py` | — | مقادیر پیش‌فرض تنظیمات |
| `settings.json` | — | تنظیماتی که از پنل مدیریت ذخیره می‌شود (روی `config.py` اعمال می‌شود؛ در گیت نیست) |
| `db.py` | — | اتصال مشترک به SQL Server |
| `auth.py` / `panel_auth.py` | — | ورود و قفل حساب (مشترک بین اپ، داشبورد و پنل) |
| `create_tables.py` | — | ساخت دیتابیس و جدول‌ها (فقط یک‌بار) |

**دیتابیس‌ها (SQL Server):**
- `tracking` — دیتابیس خودِ برنامه: `visitors`, `visits`, `orders`, `order_items`, `payments`, `submitted_uids`
- `dejavuDB1` — دیتابیس فروش موجود (فقط خواندن): جدول‌های `customer`, `article`

## ⚙️ پیش‌نیازها

- **ویندوز** با **SQL Server** (پیش‌فرض با ورود ویندوزی `Trusted_Connection`؛ ورود SQL هم از پنل مدیریت قابل تنظیم است)
- **Python 3.12** یا جدیدتر
- **ODBC Driver** برای SQL Server (`SQL Server` یا `ODBC Driver 17/18 for SQL Server`)

## 🚀 راه‌اندازی سرور (قدم‌به‌قدم)

### ۱) بازگردانی دیتابیس
فایل‌های `tracking.mdf` و `tracking_log.ldf` (داخل `DATA.rar`) را در SQL Server
خود **Attach** کنید، یا اگر دیتابیس جدید می‌خواهید فقط `create_tables.py` را اجرا کنید.

### ۲) نصب وابستگی‌ها
```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### ۳) تنظیم اولیه
اگر نام SQL Server یا IP کامپیوتر شما با پیش‌فرض فرق دارد، یک‌بار در `config.py` مقدار
`SERVER_NAME` و `SERVER_IP` را درست کنید. بعد از آن همهٔ تنظیمات از **پنل مدیریت ← ⚙️ تنظیمات** قابل تغییر است.

### ۴) ساخت جدول‌ها (فقط اگر دیتابیس را attach نکردید)
```bash
python create_tables.py
```

### ۵) اجرای سرویس‌ها (هرکدام در یک پنجرهٔ ترمینال جدا)
```bash
python app.py
```
```bash
python run_client.py
```
```bash
streamlit run dashboard.py --server.port 8501
```
```bash
streamlit run admin.py --server.port 8502
```

### ۶) باز کردن پورت‌ها در فایروال ویندوز (CMD با Run as administrator)
```bash
netsh advfirewall firewall add rule name="PeechaVisit API 5000" dir=in action=allow protocol=TCP localport=5000
```
```bash
netsh advfirewall firewall add rule name="PeechaVisit PWA 8000" dir=in action=allow protocol=TCP localport=8000
```

### ۷) دسترسی
- 📊 داشبورد مدیر: `http://<IP-سرور>:8501`
- 🛠 پنل مدیریت: `http://<IP-سرور>:8502`
- 📱 وب‌اپ موبایل (اختیاری): `http://<IP-سرور>:8000`

## 📱 اپ اندروید (APK)

اپ اندروید همان صفحات `pwa_client/` را داخل خودش دارد و آن‌ها را از یک مبدأ امن اجرا می‌کند،
برای همین **دوربین و GPS** (که مرورگر گوشی روی `http://IP` مسدود می‌کند) در اپ کار می‌کنند.

**نصب و اولین اجرا:**
1. فایل APK را روی گوشی نصب کنید (اجازهٔ «نصب از منابع ناشناس» را بدهید).
2. اپ را باز کنید و اجازهٔ **دوربین** و **موقعیت مکانی** را بدهید.
3. در صفحهٔ ورود، بخش **«⚙️ آدرس سرور»** را باز کنید، IP کامپیوتر سرور را وارد کنید
   (مثلاً `192.168.1.50`)، «تست اتصال» و سپس «ذخیره» را بزنید.
4. با نام کاربری ویزیتور وارد شوید.

> گوشی باید به همان شبکهٔ (Wi-Fi) کامپیوتر سرور وصل باشد و `app.py` روشن باشد.

**ساخت APK:**
- **خودکار:** با هر push روی پوشه‌های `android/` یا `pwa_client/`، GitHub Actions فایل APK را
  می‌سازد. در گیت‌هاب: **Actions ← Android APK ← آخرین اجرا ← Artifacts**.
- **دستی:** پوشهٔ `android/` را در Android Studio باز کنید، یا با Android SDK:
  ```bash
  cd android && ./gradlew assembleDebug
  ```
  خروجی: `android/app/build/outputs/apk/debug/app-debug.apk`

> هر تغییری در `pwa_client/` بعد از ساخت دوبارهٔ APK داخل اپ هم اعمال می‌شود.

## 🛠 پنل مدیریت

- **👥 کاربران:** آمار، جستجو و فیلتر، تعداد ویزیت/سفارش/دریافت هر کاربر، ویرایش، تغییر رمز،
  رفع قفل، فعال/غیرفعال و حذف (فقط کاربرانی که سابقه ندارند).
  برای جلوگیری از قفل‌شدن پنل، حذف دسترسی آخرین مدیر فعال یا حساب خودتان ممکن نیست.
- **➕ کاربر جدید:** با بررسی تکراری نبودن نام کاربری، طول رمز و شماره موبایل.
- **⚙️ تنظیمات:** شبکه و پورت‌ها، اتصال دیتابیس، امنیت (مدت اعتبار ورود، تعداد تلاش، مدت قفل،
  حداقل طول رمز)، نام و رنگ برنامه، ساخت کلید امنیتی جدید. تغییرات در `settings.json` ذخیره می‌شود
  و **بعد از ری‌استارت سرویس‌ها** اعمال می‌شود.
- **🩺 وضعیت سیستم:** روشن بودن API، اتصال هر دو دیتابیس و آدرس سرویس‌ها.
